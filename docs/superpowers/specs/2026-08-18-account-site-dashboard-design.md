# Account Site Dashboard Redesign

Дата: 2026-08-18

## Цель

Переработать пользовательский сайт статистики в понятную монохромную панель управления. Интерфейс должен одинаково хорошо работать на русском и английском, показывать агрегированную и початовую статистику, быстро переключать периоды и не переигрывать входную анимацию графика при каждом выборе.

## Согласованное направление

- Типографика: вариант B, спокойный humanist sans.
- Компоновка: вариант B, постоянная навигация и единая рабочая область.
- Палитра: монохромная, со светлой и темной темой.
- Скругления: небольшие, преимущественно 6-8 px.
- Liquid glass: сдержанный. Используется для навигации, панелей, селекторов и всплывающих элементов, но не превращает каждую секцию в отдельную декоративную карточку.
- Плотность: информации больше, чем сейчас, но без дублирования и бессодержательных блоков.

## Информационная архитектура

Основные разделы сохраняются:

1. Обзор.
2. Активность.
3. Мои чаты.
4. Тарифы.
5. Профиль.

Desktop использует постоянную левую навигацию. Mobile использует нижнюю навигацию с устойчивой высотой и учетом safe-area. Активный раздел визуально однозначен, а переходы между разделами не меняют геометрию навигации.

В верхней панели находятся:

- выбор контекста статистики: «Все чаты» или конкретный чат;
- текущий период там, где он влияет на экран;
- переключатель RU/EN;
- переключатель светлой/темной темы;
- доступ к профилю.

Выбранный чат применяется к Обзору и Активности. Из списка «Мои чаты» можно сразу открыть статистику конкретного чата. Если чат выключен или аналитика недоступна по тарифу, интерфейс показывает понятное состояние вместо пустого графика.

## Главный экран

Первый экран должен ощущаться заполненным за счет иерархии, а не количества текста:

- компактное приветствие и текущий контекст;
- четыре ключевые метрики;
- основной график активности;
- блок модерации;
- блок движения участников;
- короткий список подключенных чатов или лидеров активности;
- явные переходы к подробной статистике и выбранному чату.

Панели не вкладываются друг в друга. Крупные секции остаются частью общей сетки, а glass-эффект используется только там, где он помогает отделить интерактивную поверхность.

## Типографика

- Основной и заголовочный шрифт: локально подключенный Onest Variable с поддержкой кириллицы и латиницы.
- Числа, короткие технические метки и даты: системный моноширинный стек.
- Заголовки больше не используют serif italic и чрезмерно отрицательный letter-spacing.
- Размеры шрифта не зависят напрямую от ширины viewport. Используются фиксированные ступени с responsive breakpoints.
- Текстовые блоки получают предсказуемую максимальную ширину и выравниваются по общей сетке.

## Локализация RU/EN

Для небольшого сайта используется типизированный словарь без тяжелого i18n-фреймворка.

- Все пользовательские строки, aria-label, состояния загрузки, ошибки, подписи графиков и даты проходят через словарь.
- Язык по умолчанию определяется по `profile.user.language_code`, затем по языку браузера.
- Ручной выбор сохраняется в версионированном ключе `localStorage`.
- Даты и числа форматируются через `Intl.DateTimeFormat` и `Intl.NumberFormat` с активной локалью.
- Значения API и внутренние enum не переводятся в данных, переводится только представление.

## Кэш статистики

Dashboard-запросы кэшируются в памяти текущей авторизованной сессии по ключу:

```text
<chat-id-or-all>:<period>
```

Поведение:

1. При первом открытии загружается текущий контекст и период.
2. После успешной загрузки остальные периоды 1/7/30/90 для выбранного чата подгружаются в фоне с ограниченной параллельностью.
3. Повторный выбор уже загруженного периода не делает сетевой запрос.
4. При выборе другого чата сначала загружается выбранный период, затем фоново прогреваются остальные.
5. Одновременные одинаковые запросы дедуплицируются.
6. Ошибка одного периода не разрушает существующий кэш и может быть повторена.
7. Кэш не хранится в `localStorage` и очищается при выходе, чтобы аналитика аккаунта не оставалась в долговременном браузерном хранилище.

Существующий `GET /api/me/dashboard` уже поддерживает `chat_id`, поэтому новый endpoint не требуется. Backend должен дополнительно покрываться тестами на доступ к своему чату и отказ при чужом `chat_id`.

## Графики и анимация

Первое появление графика для нового контекста может использовать короткую draw-анимацию. После загрузки двух состояний переключение происходит через морфирование, а не через размонтирование компонента.

Алгоритм перехода:

- предыдущая и новая серии приводятся к общему количеству визуальных точек с линейной интерполяцией по нормализованной временной оси;
- координаты `x` и `y`, область заливки, шкала и итоговое значение интерполируются через `requestAnimationFrame`;
- длительность 320-480 ms с easing без overshoot;
- после завершения интерактивные точки соответствуют реальным данным новой серии;
- при `prefers-reduced-motion` новая серия применяется без морфирования.

Tooltip работает для мыши, клавиатурного фокуса и touch:

- локализованная дата;
- название метрики;
- точное значение;
- визуальная направляющая и выделенная точка;
- позиционирование не выходит за границы графика или viewport.

Периоды и метрики не используются как React `key` для всего графика. Это предотвращает повторную входную анимацию и потерю интерактивного состояния.

## Визуальная система

- Фон имеет небольшой контраст с рабочими поверхностями, без цветных градиентов и декоративных blobs.
- Glass-поверхность: полупрозрачный нейтральный фон, тонкая светлая кромка, умеренный `backdrop-filter`, очень мягкая внутренняя подсветка.
- В браузерах без `backdrop-filter` используется непрозрачный fallback с тем же контрастом.
- Радиусы унифицированы токенами: 4, 6 и 8 px.
- Кнопки-иконки используют понятные символы/icons и tooltip; текстовые кнопки остаются для команд.
- Hover, pressed, focus-visible, loading, disabled и error состояния проектируются для каждого интерактивного элемента.
- Все анимации меняют opacity/transform или SVG-координаты и не вызывают скачки layout.

## Адаптивность и доступность

- Desktop: фиксированная навигационная колонка и гибкая рабочая сетка.
- Tablet: более узкая навигация и перестройка вторичных панелей.
- Mobile: нижняя навигация, одноколоночный контент, фильтры в компактной верхней панели.
- Минимальная интерактивная зона 44 px для touch-контролов.
- Навигация, сегменты, селекты и точки графика доступны с клавиатуры.
- Цветовой контраст проверяется в обеих темах.
- Нет горизонтального overflow на ширинах 320 px и выше.

## Структура frontend-кода

Текущий монолитный `SiteApp.tsx` разделяется на небольшие модули:

- `i18n/` для словарей, locale context и форматтеров;
- `hooks/useDashboardCache.ts` для кэша, дедупликации и prefetch;
- `components/dashboard/` для панели контекста, метрик и вторичных блоков;
- `components/chart/` для геометрии, морфинга и tooltip;
- `screens/` для разделов сайта;
- `styles/` или упорядоченные CSS layers для токенов, layout, компонентов и motion.

Компоненты получают только необходимые данные. Статические словари и тяжелые вычисления не создаются заново на каждом render. Разделы при необходимости загружаются лениво, но базовая навигация и Обзор остаются в основном bundle.

## Ошибки и состояния

- Первый вход: полноэкранная загрузка с короткой анимацией логотипа.
- Переключение на некэшированный период: текущий график остается видимым, поверх него появляется неблокирующий loading sheen.
- Ошибка dashboard: локальная кнопка повтора, остальные разделы продолжают работать.
- Пустая статистика: нейтральная нулевая шкала и объяснение причины.
- Истекшая сессия: токен очищается, пользователь возвращается на локализованный экран входа.
- Удаленный или недоступный чат: выбор сбрасывается на «Все чаты» после подтвержденного ответа API.

## Проверка

Frontend-тесты должны покрывать:

- выбор и сохранение RU/EN;
- отсутствие непереведенных ключевых экранов;
- ключи кэша, дедупликацию и отсутствие повторного fetch после cache hit;
- prefetch четырех периодов;
- изоляцию кэша между чатами;
- морфирование без remount;
- tooltip для hover, focus и touch;
- reduced motion;
- выбор конкретного чата и передачу `chat_id`.

Backend-тесты должны подтвердить:

- агрегированную статистику;
- статистику доступного пользователю чата;
- `404` для чужого или неподключенного чата;
- отсутствие утечки данных между пользователями.

Финальная проверка включает TypeScript build, Python lint/type/tests, Playwright на desktop/mobile, обе темы, оба языка, все периоды и несколько чатов. После проверки Docker-стек перезапускается, а публичные `/site/` и API health проверяются через Nginx.

## Вне текущего объема

- Экспорт статистики в CSV/PDF.
- Реальное время через WebSocket.
- Пользовательская настройка набора виджетов.
- Хранение аналитического кэша между браузерными сессиями.
